# YOUR SLICE: S32 — desktop UI v1 (Tauri v2): Flow bar HUD, tray, hub window, config editor
Work key `S32`. Handoff note: `thoughts/shared/handoffs/general/2026-09-30_s32-desktop-ui.md`. Read the S32 section of the master slice map, including its R1 Handy notes and the open click-through design problem.

## Intent
Give dictate-agent the feel of Wispr Flow's desktop app: a small, beautiful "Flow bar" that appears the instant recording starts (live audio level, then processing, then a brief ✓/✗), a tray icon, and a hub window for history, analytics, dictionary and settings, plus an onboarding view built on `dictate doctor`. The daemon stays fully functional headless; the UI is an optional protocol client. Above all, the UI must never steal keyboard focus — injection pastes into the focused window, so a HUD that takes focus breaks the product.

## Environment (verified)
webkit2gtk-4.1, libayatana-appindicator, gtk3, node 26, bun 1.4, and `cargo tauri` are installed. Jake runs i3 on X11 (`DISPLAY=:0`); i3 is installed, so you can run `i3` inside a private `Xvfb` for tests. Never open windows on `:0`.

## Deliverables
A. **Project layout**: `ui/` with a Tauri v2 app. `ui/src-tauri` is NOT a member of the root Cargo workspace (exclude it explicitly) so `cargo test --workspace` never needs webkit; it depends on `dictate-proto` by path and on nothing that links whisper, CUDA or `dictate-core`. Frontend in strict TypeScript with a small framework of your choice (justify bundle size and startup time), bun as the package manager, lockfile committed, no network access at runtime, no telemetry.
B. **Protocol bridge** (Rust side): one long-lived connection to `$XDG_RUNTIME_DIR/dictate-agent/dictated.sock` (honor `DICTATE_SOCKET`) speaking `dictate-proto` NDJSON with handshake, subscribe, automatic reconnect with backoff, and a clear "daemon not running" state; Tauri commands that map 1:1 to protocol commands; daemon events forwarded to the webview, `audio_level` throttled to ~30 fps. Unit tests against a stub daemon (see `crates/dictate-cli/tests/cli.rs`).
C. **Flow bar HUD**: a separate undecorated, transparent, always-on-top, skip-taskbar, non-focusable window, created once and shown/hidden by state (`recording` with a live level visualization, `transcribing`/`formatting` progress, then `done`/`error`/`cancelled` for ~1 s). Position: bottom-center of the monitor under the pointer, DPI-aware. On X11: set a window type i3 floats automatically (e.g. `_NET_WM_WINDOW_TYPE_NOTIFICATION`), never accept focus, and make it click-through with an empty input shape (design and verify this — Handy never solved it). Verify with a test harness that runs `i3` inside `Xvfb`: a focused xterm keeps focus through a full show/hide cycle, the HUD floats, and pointer clicks pass through. Document the i3 `for_window` fallback rule.
D. **Tray**: status icon reflecting daemon state (idle/recording/processing/error), menu: Start/Stop dictation, Cancel, Open hub, Run doctor, Quit UI (the daemon keeps running).
E. **Hub window**: Home (WPM, words today/this week, streak, recent dictations — `get_history_analytics`, `query_history`), History (FTS search, copy, privacy indicator), Dictionary (list/add/edit/enable/disable/delete, suggestions with accept/dismiss), Settings (below), Doctor/onboarding (`diagnose` checks with their one-line fixes; highlight failures such as a missing formatter model). Snippets: omit until S24 lands (no placeholder page). Keyboard accessible, readable in light and dark.
F. **Config over the protocol** (daemon side, owned by you): implement `get_config`/`set_config` (`config_read`/`config_write`, local connections only): read the effective config and the user's file, validate every write through the same loader `dictated --check-config` uses, write atomically (temp file + rename) preserving comments and unknown keys (`toml_edit`), keep one backup, and report which keys need a daemon restart (`ConfigSnapshot.restart_required`) versus apply live — only claim live application where you implemented it. Control-plane tests: round trip, validation errors are `config_invalid` with the offending path, capability denial, comment preservation. The Settings page is a structured editor for the common keys plus a raw TOML editor with validation feedback.
G. **Build and run**: `just ui-dev`, `just ui-build`, `just ui-test`; README section in `ui/README.md`; how to autostart with i3 (`exec --no-startup-id …`), documented, not installed.
