# S03 — headless end-to-end latency, memory and startup (numbers only)

No transcripts, window titles or personal data: the audio is the committed
synthetic espeak-ng fixtures (`crates/dictated/tests/fixtures/e2e/`, invented
sentences, 16 kHz mono). The robotic voice is easy for Whisper, so **WER here
says nothing about real-voice accuracy** — only about plumbing and model health.
Every latency below is *machine-dependent* and *load-dependent* (see "Noise").

## Environment

| | |
|---|---|
| GPU | NVIDIA GeForce RTX 5080, 16 303 MiB, driver 615.71.09 |
| Model | `large-v3-turbo` (`ggml-large-v3-turbo.bin`, 1 624 555 275 B, SHA-256 verified) |
| Build | `--release` (opt-level 3, LTO), whisper.cpp with CUDA |
| Host | Arch Linux, kernel 7.2.6-zen2, 32 hardware threads, other workers building concurrently (load avg 8–21) |
| Daemon | in-process (`e2e-real` test) and the release `dictated` binary; audio-less; VAD = Silero, LLM pass off; language pinned `en` |

## Per-stage warm latency (ms) — `just e2e`, in-process daemon, release

Eight measured runs per clip after one warm-up; p95 of 8 samples is effectively
the maximum. `capture` for an upload is decode + resample (the clips are already
16 kHz mono, so this is a pass-through). `request wall` is send → response on the
socket, base64 and JSON included.

| clip | audio | capture p50/p95 | vad p50/p95 | stt p50/p95 | total p50/p95 | request wall p50/p95 | stt RTF (p50) | WER |
|---|---|---|---|---|---|---|---|---|
| short | 3.3 s | 0.4 / 0.5 | 5.6 / 5.7 | 105.4 / 108.4 | 111.0 / 113.7 | 111.7 / 114.4 | 0.032 | 0.000 |
| medium | 9.3 s | 1.0 / 1.5 | 15.4 / 16.0 | 135.0 / 135.6 | 150.0 / 151.6 | 151.7 / 153.2 | 0.014 | 0.000 |
| long | 33.3 s | 3.6 / 3.7 | 53.8 / 54.6 | 332.8 / 337.2 | 385.3 / 388.7 | 391.0 / 394.2 | 0.010 | 0.000 |

`fmt_rules`, `fmt_llm` and `inject` are not in the table: the rules layer has no
separate stage until S20, the LLM pass was disabled, and an upload delivers text
rather than injecting it. Budget check (integration contract §4: end to end
≤ 1.0 s p50 for a 10 s utterance): **150 ms** for the 9.3 s clip, before the LLM
pass and injection.

First request after process start (release `dictated`, driven by `dictate
transcribe`; three runs, n small): short 169–192 ms total (vad 35–41, stt
134–151), medium 148–154, long 392–412. The extra ~30 ms on the first short clip
is Silero and CUDA warming up (warm short is 111 ms).

## Startup (release `dictated`, isolated environment, model in page cache)

Three runs: 348–463 ms.

| milestone | after `exec` |
|---|---|
| control socket bound | 54–66 ms |
| model resident on the GPU (`get_status` reports `loaded`) | 348–463 ms |

Cold page cache: reading the model with `O_DIRECT` took 0.47 s (3.4 GB/s), so a
genuinely cold start is roughly 0.85–0.95 s. (Not measured directly: dropping
the page cache needs root, which this task did not use.) In the in-process test,
`WhisperStt::new` → model loaded is 169–274 ms.

| | value |
|---|---|
| GPU memory held by the daemon, model loaded, idle | 2 198 MiB (`nvidia-smi --query-compute-apps`, this pid) |
| GPU memory after transcribing the 33 s clip | 2 356 MiB |
| whole-GPU usage at the time (every process) | 6.0–6.3 GiB of 16.3 GiB |
| host RSS, idle after load | 441 MB (peak 572 MB during load) |
| host RSS after transcribing all three clips | 631–695 MB |
| idle CPU, audio-less, 10 s window | 0.1–0.2 % of one core |
| `dictate doctor` SHA-256 verification of the 1.6 GB model | 0.6–0.7 s |

`systemd/dictated.service` sets `MemoryMax=4G` and `CPUQuota=80%`: peak RSS is
~17 % of the former; the latter caps the daemon at 0.8 core, which is worth
re-measuring with the microphone armed (pre-roll callback) and the LLM pass on.

## Cancellation under real load

Cancelling a 33 s upload mid-decode and immediately sending a 3.3 s upload: the
second was answered in 361–435 ms (WER 0.000) — the daemon is not wedged by a
cancelled real transcription, and the wait is bounded by the ~330 ms the
abandoned decode still needs (Whisper's `full()` cannot be interrupted).

## Noise

- One 48 kHz-mono run showed stt 526 ms against a steady 334 ms for the
  equivalent stereo runs; the GPU and CPU were shared with other workers'
  builds. Treat single outliers as contention, and the p50 columns as the
  steady state.
- Timings are wall-clock inside the daemon (`StageTimings`), so they include
  scheduling on a loaded box.
- Reproduce: `just e2e` (in-process, five tests), `scripts/smoke-real.sh`
  (release binaries, pass/fail), `scripts/measure-startup.sh` (startup, memory,
  upload formats).
