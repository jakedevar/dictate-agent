Implemented protocol v1 in a new lightweight, synchronous `dictate-gpu-gate`
crate, with `dictate-gpu-status` and `dictate-gpu-gate` binaries. No Whisper,
CUDA, audio stack or async runtime dependency. The status socket is
`%t/dictate-agent/gpu-status.sock`, systemd Accept=yes, 0600 with a 0700 directory.
It observes systemd and legacy-process state, handshakes with dictated and asks
`get_status` only while active, then returns one JSON line. It never starts the
daemon. Read-only probes and replies are bounded.

`dictated.service` now runs the interlock in ExecStartPre with a 180-second start
timeout. The helper sends the exact v1 operation, holder, random v4 intent UUID
and deadline, waits for a reply, and always permits startup. Default op and
Playboy socket path are constants; environment overrides and an optional
separate TOML file support protocol/deployment changes. No response in 90 seconds
logs gate_timeout; absent/refused sockets proceed immediately; invalid/refused
replies warn and proceed. The legacy launcher requires DICTATE_ALLOW_LEGACY=1,
then runs the helper first (and refuses if the helper is missing).

Engineering/product choices and assumptions:

- Emit status immediately, supporting connect-and-read clients and clients that
  send the optional status request. No request is needed to get a snapshot.
- Keep gate config independent of the shared dictation config. Load it only when
  DICTATE_GPU_GATE_CONFIG explicitly names it; env takes precedence. Deadline
  overrides may shorten but cannot extend the 90-second ceiling.
- Check the legacy PID's comm: dictated claims the same legacy PID file, so
  liveness alone would falsely report a legacy process. A separate comm scan
  still catches legacy starts without a PID file.
- Preserve the runtime directory across dictated shutdown so its inactive
  state remains queryable through the independently activated status socket.
- `since` is systemd's service transition estimate; model-ready timestamps are
  unavailable. Legacy/no-timestamp observations use observed_at. GPU booleans
  report dictated's control response only; legacy-only on has false GPU flags.
  Consumers must use state for exclusion. CPU-ready dictated is on per v1.
- Keep v1 fail-open behavior: a warning can mean temporary overlap. PlayboyAI
  must also consume the status; this helper is not a durable lease protocol.
- The Mac DictateHub fallback cannot start hub dictation: its stopped-hub
  tunnel connection is refused. The Mac-local daemon is unchanged.

PM install steps (worker did not execute):

1. Integrate the reported final SHA. Build `cargo build --release -p
   dictate-gpu-gate`, keeping the designated cargo target/settings. Install the
   two helper binaries from its release directory to ~/.local/bin (0755).
2. Install systemd/dictated.service, systemd/dictate-gpu-status.socket and
   systemd/dictate-gpu-status@.service to ~/.config/systemd/user (0644), retaining
   intentional local overrides. Ensure the legacy login launcher uses the
   merged scripts/run.sh. Do not remove the retained dictate-agent binary.
3. Run `systemctl --user daemon-reload`, then
   `systemctl --user enable --now dictate-gpu-status.socket`.
4. Leave dictated.service stopped. Querying the status socket should return off
   without starting it. A later, separately authorized service start/boot/restart
   will run the gate. Do not use the generic installer's suggested dictated
   enable/start command during this rollout.
