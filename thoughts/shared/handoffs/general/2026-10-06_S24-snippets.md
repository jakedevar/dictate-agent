## Design

* **Storage** — `crates/dictate-dict/src/snippets.rs`; same `dictionary.db` and same
  `Dictionary` handle as the dictionary (an `RwLock<Arc<SnippetMatcher>>` snapshot beside
  the dictionary's, a separate hit queue flushed by `flush_hits`). Additive to S22: `store.rs`
  gets the migration + `conn` made `pub(crate)`; `lib.rs` gets two fields, one `new` line and
  one `flush_snippet_hits` call.
* **Matching** — on words, not substrings: case-folded tokens, whitespace/simple punctuation
  allowed between trigger words (Whisper's `"Insert, work email"`), longest trigger wins,
  no overlaps, whole words only, per-app scope (same rule as the dictionary: empty = global,
  no context = global only). A trigger that ends the utterance swallows the sentence
  punctuation Whisper appended (`"Insert work email."` → expansion alone); mid-text
  punctuation stays. Uniqueness is on the folded word sequence (`"My  Address"` = `"my address"`).
* **Chain stage** — `dictate-core/src/snippet_stage.rs`, `Slot::Snippets`, assembled by
  `dictionary_stage::assemble_text_chain` right after the dictionary (contract §1 order).
  Expansion is `Edit::protected(.., SpanKind::Snippet)` (the kind already existed): no rule can
  recase/respace it and `verify_output` rejects an LLM that edits or drops it. Honors
  `ctx.use_dictionary`, `[dictionary] enabled`, `ctx.persist` (privacy → no hit counts).
* **Variables** — `{date}` (`%Y-%m-%d`), `{time}` (`%H:%M`), `{clipboard}`, `{selection}` (X11
  PRIMARY via arboard). Single-pass `regex` replace (a clipboard containing `{date}` is not
  re-expanded); `{{date}}` → literal `{date}`; unknown `{x}` untouched. Resolved lazily — only
  for variables a *matched* snippet uses. Values are sanitized (placeholder/private-use chars and
  non-\n\t controls stripped, 10 000-char cap) because one stray placeholder would make the
  whole `apply_edits` batch fail. An unavailable clipboard expands to "".
* **Proto** — `Snippet` gained `apps: Vec<String>` and `hit_count: Option<u64>`
  (additive, `skip_serializing_if`, golden-pinned incl. a minimal-form pin). Existing
  `ListSnippets/UpsertSnippet/DeleteSnippet` + `Snippets/Snippet` results are now implemented
  in `server.rs`; capabilities `snippets_read/write` are on (off when no dictionary store).
* **CLI** — `dictate snippet list|add|rm|enable|disable` (`add <trigger> <text|->`, `--file`,
  `--app`, `--category`); `snippet.rs`, renders in `render.rs`.
* **Docs** — `docs/protocol.md` "Snippets (S24)", AGENTS.md note.

## Migration 3 (for the pre-merge review)

Applied by the existing runner (`store.rs`): `user_version`-gated, each migration in its own
transaction, `user_version = index+1` set inside it, DB newer than the daemon refused.
`SCHEMA_VERSION` 2 → 3. Exact SQL (`store::MIGRATION_V3`):

```sql
CREATE TABLE IF NOT EXISTS snippets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trigger_text TEXT NOT NULL,
    trigger_key TEXT NOT NULL UNIQUE,
    expansion TEXT NOT NULL,
    category TEXT,
    apps TEXT NOT NULL DEFAULT '[]',
    enabled INTEGER NOT NULL DEFAULT 1,
    hit_count INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

Purely additive: one new table, `entries` is not touched (so no dictionary row can be lost);
`IF NOT EXISTS` makes a re-run harmless. Column is `trigger_text` (not `trigger`) to stay clear
of the SQL keyword. `trigger_key` = folded words joined by one space (the uniqueness key).
Timestamps are ms since epoch like `entries`. Tests (`crates/dictate-dict/tests/snippets.rs`):

* `migration_3_adds_the_snippets_table_and_keeps_every_dictionary_row` — builds a real v2 DB
  (V1 + the `apps` ALTER, `user_version=2`, two populated `entries` rows incl. hit_count/apps/
  timestamps), opens it through `DictionaryStore::from_connection`, asserts both rows and every
  field survive and the new table is empty and writable.
* `migration_3_is_forward_only_and_idempotent_across_reopens` — on-disk WAL DB: two reopens keep
  data, `user_version == 3`, re-executing `MIGRATION_V3` is a no-op, `user_version=4` is refused.
* `dictionary.rs::persistent_wal_store_reopens_without_losing_metadata` — existing test's expected
  `user_version` changed 2 → 3 (the only existing-test edit in dict).

## Deviations from the spec / things the integrator must know

1. **Extra proto fields** `apps`, `hit_count` on `Snippet` (spec: per-app scope + usage counts).
2. **`FormatContext.host_variables: bool`** (new field, default `false`, set `!upload` in
   `pipeline.rs`). Needed so an uploaded recording (`transcribe_audio`) cannot read the desktop
   user's clipboard by saying a trigger. The one test that builds a literal `FormatContext`
   (`dictated/tests/formatting.rs`) gained `host_variables: true`.
3. **Routing**: the router runs on the restored rules text, so an expansion starting
   `timer …`/`edit: …`/`easy …` would have been routed (verified: it set a timer). The pipeline
   now skips the router when the utterance *opens* with a snippet span (typed as Type). A
   snippet mid-utterance is unaffected (route words are prefix-only). Test:
   `an_expansion_that_looks_like_a_route_trigger_is_typed_not_routed` (fails without the fix).
4. No `[snippets]` config section; snippets follow `[dictionary] enabled` and
   `use_dictionary`. No UI page (spec lists proto/CLI only; the S32 hub's Dictionary page was
   not extended — needs tauri commands + a page; follow-up).
5. A trigger with the same words as another is a `conflict` even if their app scopes differ
   (UNIQUE on `trigger_key`) — no per-app override of a global trigger.
6. `{clipboard}`/`{selection}` read through arboard synchronously inside the (inline) chain;
   a hung X11 selection owner could stall that one dictation (bounded by arboard's own timeout).
   Only paid by snippets that use those variables. Wayland: arboard fails → empty.
7. Touched outside S24 ownership: `dictionary_stage.rs` (assembly adds the Snippets stage),
   `pipeline.rs` (host_variables + route guard), `dictate-fmt/src/text/mod.rs` (the field),
   `dictated/{lib,server}.rs`, `control_plane.rs` (the "unsupported command" test now uses the
   audio-stream commands, still unimplemented), `golden.rs`. Did not touch `llm/*` or
   `llm_formatter.rs`.
