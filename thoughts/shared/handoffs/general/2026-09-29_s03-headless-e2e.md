## Decisions the integrator must know (with reasons)

1. **An upload is a session with a handle flag, not a second pipeline.**
   `SessionHandle::new_upload` carries the decoded samples; `pipeline.rs` gained
   only: `let upload = handle.is_upload()`, three `!upload` guards (Recording
   notice, media pause, capture cancel/media resume), `take_audio()` where the
   capture flush was, the `capture` timing = decode cost, `earcon()` early-return,
   default `CaptureDiagnostics` for uploads, and `total_ms += prepare_ms`. The
   VAD→inject body is untouched. The engine pre-stores the stop permit so the
   existing wait passes straight through (cancel still wins: the select is biased).
2. **Uploads skip `recording`** (`idle → transcribing`): legal under the state
   machine; a HUD must not flash "recording" for a file.
3. **Decode happens before the engine slot is claimed**, on the blocking pool:
   a malformed/oversized upload is a request error and never makes a good
   dictation answer `busy`. Cost: a busy daemon decodes then refuses (bounded by
   `[upload]` limits, local trusted socket).
4. **`inject` for uploads defaults to false even on a connection that may type**
   (`resolve_upload_options`), unlike `start_dictation`. `Some(true)` still needs
   `text_injection` (else `forbidden`, never a silent downgrade).
5. **Router still runs for uploads** (spec order kept), so a WAV that says
   "set a timer for five minutes" starts a timer for a local-trusted caller.
   `--route type` forces plain text. [decision for Jake if unwanted: force
   `Route::Type` by default for uploads — one line in `resolve_upload_options`.]
6. **Ownership**: new `SessionOwner::Upload(client)`: cancellable by the
   uploader, any `host_capture` peer (`dictate cancel` in another terminal) or a
   signal; **cancelled when its connection goes away**, and the server watches
   for hang-up during the wait — so an interrupted `dictate transcribe --inject`
   never types afterwards. Side fix: `handle_connection` now always tells the
   engine about a disconnect (a failed write used to skip it).
7. **Limits** come from `Capabilities.limits` (`[upload] max_audio_seconds=600`,
   `max_bytes=64 MiB` → `max_message_bytes`, `max_audio_ms`); duration is checked
   from the WAV header before decoding. Errors: `payload_too_large` (with
   `{limit,actual}`), `audio_format_unsupported`, `invalid_params`,
   `capability_unavailable` (stream/body sources = S33).
8. **Resampler is Kaiser-windowed-sinc polyphase, own code, no new dependency**
   (rubato's API churns; ours is 100 lines with tests that measure passband
   gain, >60 dB out-of-band rejection vs naive decimation aliasing at full level,
   and 8.8 kHz→7.2 kHz alias rejection). Optimised 7×: 33 s stereo 48 kHz →
   30 ms.
9. **Config**: `serde_ignored` (new dep) reports ignored keys so other slices'
   new sections are known automatically; `[router]`→`[local]` and HF ids are
   *mapped* with a warning (June ignored `[router]`; values identical for Jake);
   values that would panic later (`timeout_s <= 0`, device typo) are load errors.
10. **Doctor runs in the daemon**; the CLI adds the `daemon` check and works with
    no daemon. Read-only everywhere (never deletes a stale PID file). `formatter`
    health = observed (startup probe + real runs); one WARN + **one** desktop
    notification per journey into failure; a length-ratio rejection is *not* a
    failure. CUDA is verified against `nvidia-smi` because the STT `backend` field
    echoes the request (Issue filed).
11. Doctor/startup semantics: no `$DISPLAY` → `warn` (headless is legitimate),
    display set but unreachable → `fail`; audio input `ok` with an explicit
    privacy sentence when armed while idle.
