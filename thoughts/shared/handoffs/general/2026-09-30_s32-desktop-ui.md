## Decisions (with reasons)

1. **Click-through under i3 needs the input shape re-sent after every map.**
   The first Xvfb run failed: clicks on the bar went to i3's *frame* window.
   i3 copies a client's input shape to the frame only on a `ShapeNotify`
   received after managing the window (at manage time it can only query the
   bounding shape) and builds a new frame per map. `x11.rs` now re-applies the
   empty region to the realized `GdkWindow` on every `map-event`; i3 then
   shapes the frame. Same handler re-asserts `accept_focus(false)`.
2. **Placement drift.** i3 placed each re-mapped floating window with its
   title-bar offset (+2, +22) although the bar is borderless (motif hints are
   honored: `_NET_FRAME_EXTENTS = 0`), so the bar crept down 22 px per show.
   The exact move (logical px, kept in a shared `Pin`) is re-issued after map.
3. **Managed notification window, not override-redirect.** Kept the brief's
   design (i3 floats `_NET_WM_WINDOW_TYPE_NOTIFICATION` with no rule). The two
   map-time fixes make it exact; override-redirect would have avoided both but
   gives up WM stacking/sticky semantics and the documented i3 fallback rule.
4. **Lost-update protection for config writes** (tier-2 review item).
   `ConfigFile.revision` (FNV-1a of the text, opaque) + optional
   `set_config.base_revision`: a stale editor gets `conflict` (with the current
   revision) and nothing is written. Independently, the daemon re-reads the
   file just before the rename and refuses if it changed during validation.
   Both fields are additive, golden-pinned, documented in `docs/protocol.md`,
   and were added before any released daemon implemented `set_config`.
5. **Legacy `[grammar]` files are edited through `[grammar]`.** Since S21 the
   daemon reads `[grammar]` only while `[format.llm]` is absent; writing
   `format.llm.*` into Jake's Python-era file would create `[format.llm]` and
   silently discard his `[grammar]` settings. `settings.ts` detects the layout
   from the file's headers (`usesLegacyGrammar`) and picks the field set;
   unit-tested both ways (commented headers ignored).
6. **Dismissing a dictionary suggestion stores it as a disabled entry.** The
   daemon never suggests a phrase the dictionary holds, so this makes a
   dismissal persistent without a new protocol command; a disabled entry
   changes no transcript and can be enabled or deleted later.
7. **`--hub [page]`** start option (parsed and unit-tested) — used by the
   screenshot script and handy for an i3 binding.

## Tier-2 review notes

**Config-write safety** (`config_rpc.rs`): one validator (the startup loader;
invalid → `config_invalid` + offending path, nothing written); `toml_edit`
keeps comments/order/unknown keys; temp file in the same dir (`create_new`,
original mode restored exactly), fsync, one `.bak` copy, rename, dir fsync;
symlinked configs written through to the target; RPC writers serialized by a
mutex; local connections only (`remote_transcription_only` never grants
`config_read`/`config_write`); dry runs never write. New: revision guard and
pre-rename re-read (above). Residual: a hand edit landing in the microseconds
between the re-read and the rename is still overwritten (`.bak` holds the
replaced text); the `.bak` copy itself is not fsynced (the primary file is).

**Focus stealing:** the bar is verified end to end (below). The hub takes
focus only on explicit user action (tray Open hub / Run doctor, `--hub`) or at
start when no tray exists. No notifications, no other windows.
