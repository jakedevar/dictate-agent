## Reconciliation

- Normal paste and EDIT use `PasteSelection::transfer_to(window)`: filter by
  X11 resource client base, reject other clients, and validate focus and ownership
  under a server grab before transferring. This retains S13b's destination
  consumption attribution and S25's restriction on who receives the replacement.
  Completion is still a heuristic; apps using separate clipboard connections
  may time out conservatively.
- Raw clipboard snapshots, property types/formats, snapshot-to-claim guarding,
  concurrent-copy ownership and restoration by changing the served contents are
  shared by both routes. Ctrl+C and Ctrl+V use one atomically focus-checked XTest
  chord implementation. Selection capture records the exact observed copy owner;
  restoration cannot overwrite a new owner even on the same application client.
- Ordinary unconfirmed paste retains dictation for a late/manual request and never
  restores old contents or retries typing. EDIT preserves the prior clipboard
  and refuses late requests from the destination client after an uncertain paste.
  This prevents stale clipboard text replacing the selection. That client must
  copy again before it can manually paste the restored clipboard; other clients
  retain access. Successful EDIT restores normally. Concurrent copies always win.
- Stop captures focus once through `TextInjector::capture_destination` into the
  existing shared `ResolvedOptions::stop_destination`. Explicit stop captures
  before waking the pipeline; automatic stop fills the same slot. EDIT reads
  this identity, including failed captures, without recapturing during STT.
  Removed S25's duplicate SessionHandle latch. `edit_destination`,
  `capture_selection`, `replace_selection` and `inject_bound` remain available;
  the default capture seam supports existing edit-destination adapters.
- Keep `EditPreview`, `EditError` and `InjectionFailed`. EDIT raises its own
  notification, avoiding a duplicate InjectionFailed notice. All failures still
  set history's error summary; none of these notices overwrites the clipboard.
- S25's Xvfb fixture now runs inside a subprocess with only its allocated private
  DISPLAY and no inherited WAYLAND_DISPLAY/XAUTHORITY. Extended it to verify a
  late request after an ignored Ctrl+V receives no payload and changes no text.

Resolved the four named conflicts plus selection.rs, pipeline.rs and session.rs
where the old clipboard API and duplicate destination latch needed adaptation.
Narrow test/docs changes: mock destination counter, daemon EDIT assertions,
x11_edit.rs isolation and late-request checks, and docs/edit-mode.md.
Master's S24 and other cleanly merged changes are retained unchanged.
